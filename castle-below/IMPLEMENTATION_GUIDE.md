# Castle Below 正式版實作指南

目前試玩版包含地下試煉長廊、三個一般試煉、雷焰惡龍及可往返的一樓探索區。從 [試玩入口](index.html) 進入，對照 [Canvas 實作](gameplay-demo.html) 和 [正式素材](assets/) 還原。這份指南使用程式中的函式與欄位名稱，方便在換引擎或拆模組時查到對應邏輯。尺寸、速度和透明度是試玩版的調校基準。

## 1. 建立可比較的遊玩基準

試玩版用原生 Canvas 2D 和 DOM，直接開啟 `index.html` 即可離線玩。要測試 HTTP 入口，可在儲存庫根目錄執行 `python3 -m http.server 8000`，再開啟 `http://localhost:8000/castle-below/`。先跑一趟完整路線，再開始做正式版的場景或系統。

- 從地下試煉長廊的岩漿門前出發。進門時關卡昏暗，點石臺上的卷軸即可選英文規則。按「Begin」後卷軸台和命中區一起消失，長廊原地亮起。中途仍可用「閱讀卷軸」重讀。
- 一般試煉使用 Coji 背後的正向透視鏡頭。岩漿長廊連續 54 排、五條路線，玩家點地板決定目的地，Coji 可前進、後退或橫移，到點停下。岩漿關會將點在 Coji 身上的操作投影到地板。入口石臺寬五格。Coji 的出生列是可後退的界線，後方延伸的石地與側牆供鏡頭取景。金屬門檻外才是危險區。三秒預警期間，整片危險地面逐步亮起並淹沒符號，地下室暗處持續飄煙，升溫時同一團煙逐漸映出紅光，黑區與走道共用帶光暈的餘燼粒子。岩漿爆發的瞬間播放「Floor is lava!」，壁掛火盆向上噴焰。岩漿維持七秒，再用 2.5 秒冷卻回石地，冷卻結束後才能移動。安全格分散在流動岩漿中。踩錯時 Coji 會喊「HOT HOT HOT!!」並飛回入口，保留生命。藍石、月亮、綠星及避開紅月四種固定規則各有 60 秒可操作時間，帽頂只顯示剩餘秒數，最後十秒數字轉為暖紅色。讀卷軸、岩漿和冷卻期間停表，踏上終點平台即完成計時。超時可從入口重試。選 Castle banners 則每輪從藍月、綠星、紅菱形中抽出與上一輪不同的標記。爆發前三秒，地下室盡頭的爐房牆上，門洞兩側各垂下一面織布長旗。收放時整塊旗布垂直平移，橫桿上方裁切。兩旗顯示相同標記，從長廊入口即可辨讀。石板原位保留，每兩排都提供三種標記，旗幟、岩島和傷害判定共用當輪標記。終點有六排安全平台，和守門人談過雷焰惡龍後，門縫逐漸映出後方通道，門內的柔光從遠端拱門緩緩擴散、收回，最亮時仍能看清火把與石柱，穿過光門會回到試煉長廊。
- 從長廊可走回地下樓梯廳，沿樓梯抵達遺忘大廳、挑戰小怪。樓梯廳另一側通往地下石廳，再連到地下檔案室、石匣室和藏寶室。
- 王座裂谷從 Coji 身後看向遠端石階的惡龍。點前景石地橫移、點龍施放光球，按住 Coji 展開魔法盾。每個血量階段都交替使用閃電和噴火。雷雲朝同一方向循環，雲隙亮處固定，光暈隨雲層厚度起伏。惡龍抬頭召雷時，全場迅速暗下，雲間分支閃電接連亮起。地面電弧標出落點，落雷時有爆塵、飛石、雷聲和震動。噴火時全身泛起火光，雙翼完全展開。兩次吐息的橫掃方向相反，龍口位置、火柱和碰撞共用同一段動作。火柱掃過的石面逐段裂開，發光熔岩先冷卻，裂痕再消退。盾面會截斷火柱，遮住的地面保持完整。傷害只在火柱掃中時結算。目前試玩將龍的血量設為 1 HP。致命一擊觸發一次龍吼，雷火沿龍翼與軀幹交錯。龍在約 3.65 秒內仰頭、屈膝、伏地，頭頂三波群雷隨後消退。天空於第 6.15 秒恢復，第 6.6 秒顯示通關卷軸。Coji 落敗則在龍振翅咆哮後滿血重試。

  王座上空使用可水平循環的雲圖 `storm-wind-loop.webp`。製圖時先將兩端重疊漸混，再從同一片雲的連續紋理裁出循環邊界，以無損 WebP 儲存。每幀以同一個 Canvas 2D `repeat-x` 圖樣填滿天空，把圖樣沿水平方向每秒平移 4.5 個場景像素，週期寬 1500。固定前景 `storm-throne-foreground.webp` 以透明通道保留窗花、塔尖和遠山輪廓，窗洞內外共用同一片移動天空。調整後可將時間設為約 197 秒，讓接縫通過王座中央，並以橫向、直向及非整數像素縮放檢查是否出現細線。
- 地下樓梯廳的另一扇拱門通往試煉長廊。三扇一般門分別通往岩漿長廊、幽靈引路與魔眼走廊，第四扇門可直接挑戰雷焰惡龍。「設定」內也能直接前往長廊。
- 幽靈引路的三間房都寬七格。入口卷軸一次給出英文線索，保留六種物品與騎士的配對。三個幽靈都會招呼 Coji，也都會帶路。跟錯幽靈要等進入鐵柵門後才揭曉。撿起鑰匙或水晶時，Coji 帽頂會顯示同一件物品的小圖。換物時更新，交付或重來時消失。硬闖時，最近的守衛會從當前位置走來攔路，頭頂台詞與英文配音同步。玩家改走另一側或退回時，每位守衛都從原地繼續走。把鑰匙或水晶交給錯的騎士，或交錯物品，Coji 會飛起。最後房間的兩尊雕像採微俯視視角，左右翻面時以石座為中心，各自指向不同的門。玩家靠手勢辨認方向，點雕像可查看它的低語。門上省略左右標籤，選錯會回到幽靈房。三種失敗都清除沿途進度，保留本次卷軸規則。反向線索須能唯一判定答案，三位騎士須排除兩色，兩尊雕像只需排除一色。
- 幽靈房和岩漿長廊的端牆向下延伸時，將磚材以固定世界尺寸重複鋪設，鏡頭靠近或貼邊時仍維持相同的磚縫密度。火柱、柵門和浮雕獨立繪製。
- 地下石廳有琥珀碎片，藏寶室有月光石。走到寶箱前開箱，再點地上的道具拾取。
- 原路回樓梯廳，再回一樓。同層六個拱門和上下樓皆可雙向通行，試玩可以持續探索。
- 處理場景問題時打開「格線」檢查可走範圍和角色框。「畫面效果」可隔離窗光、燈光和霧。「重置」會恢復角色、敵人和物品的初始狀態。

### 場景拓撲和尺寸

`rooms` 定義各房間，`upperFloor` 和 `lowerFloor` 定義樓層與門的連線。`bounds` 以下列半開區間表示，沿左、上邊界包含該座標，沿右、下邊界交給相鄰房間。這讓角色腳點跨線時只屬於一間房。

| 房間 | 資料鍵 | x 範圍 | y 範圍 | 交互與美術 |
|---|---|---|---|---|
| 玻璃大廳 | `gallery` | 34–66 | 5–34 | 三面窗、中央石牆與巨型騎士、另外三面窗。一樓安全復位點 `(51.5, 9.5)` |
| 遺忘大廳 | `hall` | 5–34 | 5–34 | 三處窗光、Shadow Imp、地板內向下的樓梯 |
| 地下樓梯廳 | `cellar` | 7–30 | 7–27 | 貼牆的回樓梯、連中央石廳 |
| 試煉長廊 | `corridor` | 7–19 | 27–63 | 三種試煉及雷焰惡龍的入口。試玩起點 `(9.5, 30.5)`，面向岩漿門 |
| 地下石廳 | `vault` | 30–53 | 7–27 | 四邊通往相鄰房間、琥珀碎片寶箱 |
| 地下檔案室 | `archive` | 31–51 | −16–7 | 以書架、石牆和燈柱照明區別房間 |
| 石匣室 | `ossuary` | 31–51 | 27–50 | 石匣、雕刻和鏡射過的房間素材 |
| 藏寶室 | `treasury` | 53–76 | 7–27 | 鐵柵、寶箱與月光石 |

同層共用牆有唯一的世界平面。在一樓，兩個大廳的 y 範圍相同，門位於 `x = 34`。地下石廳四面的門在 `x = 30`、`x = 53`、`y = 7`、`y = 27`。繪圖前先確定這些邊和門的位置。

一樓的連線可直接當成新增拱門的資料範例。這條邊是遺忘大廳的右邊界和玻璃大廳的左邊界，兩房可沿 y 軸的重疊區接合。門柱和石檻取自玻璃大廳的原圖。

```js
{
  axis: "x",
  at: 34,
  jambs: [256, 353],
  sill: [521, 470],
  before: rooms.hall,
  after: rooms.gallery
}
```

`before` 和 `after` 分別在牆軸座標較小和較大的一側。它們是幾何關係，玩家可以從任一側穿過。新增連線時檢查門柱投影後落在兩房共用邊的範圍內，並至少留下足夠一格正向跨過的開口。

## 2. 場景素材怎麼畫

### 擬真素材與遊戲鏡頭

場景、角色、怪物、雕像、道具及壁掛器具都用擬真圖像。先找現有素材，新增時可用照片或生成擬真圖。石材的刻痕、金屬的反光、布料的皺褶應在遊戲尺寸下仍看得出來。手繪扁平 2D 圖和 Canvas 幾何佔位圖只供原型定位。正式畫面用 Canvas 投影、裁切與排列素材，並即時合成火焰、煙霧、光暈、粒子及互動提示。

探索樓層使用 2:1 等角鏡頭，一般試煉使用 Coji 背後、沿走廊向前的微俯視鏡頭。依目標鏡頭製作素材。例如指路雕像應看得到肩甲與石座的上表面，手指方向在手機上也要看得清楚。道具輸出為透明底、保留原比例的 WebP，地上的物品與帽頂的持有提示共用同一張圖。製作 Coji 和 Bebear 時沿用[角色參考](assets/ASSET_REFERENCES.md)。

### 房間構圖與拼接

1. 用可走格畫出要連接的矩形房間，指定寬、深、門所在的牆軸與門檻位置，以及同層的牆高。大廳要留出足夠的地板，讓角色移動時還有房間的尺度感。
2. 探索樓層的房間底圖採固定方向的 2:1 等角投影，保留完整的無屋頂視野。底圖正面兩邊的完整外牆由遊戲裝配，底圖提供地板和後方兩面牆。生成時保留四個地板角、牆頂、牆腳和拱門全貌，避免畫布裁到這些位置。
3. 一樓沿用寫實哥德石材、偏冷玻璃及濕潤石板反光。地下室用較深的風化石材和暖色燈柱。各室可用書架、鎖鏈、石匣、鐵柵或雕像區分。場景基礎材質應能接在一起。
4. 窗、燈、雕像、門檻要有清楚的接地或附牆位置。獨立的燈柱、美術特效、玩家、敵人、寶箱、掉落物各自輸出，以便在遊戲中正確排列深度和改變狀態。
5. 拱門要保留有厚度的門柱、石拱及石門檻，門洞內的預畫景色會按內輪廓挖空。生成圖的視覺預覽可以畫暗門洞，配準時要能識別並剔除洞內原本的畫面。背景使用透明或與牆頂易於分離的暗色，以利去除取樣進來的底色。
6. 把新圖放進實際相鄰的兩個房間，檢查牆頂銜接、門洞視線、地板色差及角色站立位置。先過這一步再大量產出房間。孤立的一張生成圖只能驗收畫風，拼接後的效果要從遊戲鏡頭看。

### 物件接地與接觸陰影

先把角色的承重腳、家具底座或門檻標在素材上，量出它到圖片頂端的高度比例。將這個點對準世界地面的投影，再由同一組繪製座標計算命中區。正向試煉的卷軸台以圖高的 91.5% 為落點，最前方的台腳會蓋住這個落點。角色圖集逐幀使用 `footInset`。呼吸和待機以腳底為縮放原點，轉向時角色和接觸陰影一起鏡射。

`drawFootContact` 從目前那一幀下方 16% 的透明輪廓取樣，依輪廓製作接觸陰影並快取。先畫陰影，再以相同姿勢畫本體，只露出約半到兩個畫面像素的暗邊。兩腳之間、桌腳之間都應看得到原來的地板。這套畫法用於試煉家具與守門人，也用於 Coji、小怪、燈柱與寶箱。飛天時地面投影可和角色分離。

驗收時依序看正面、左右靠牆、手機直式，以及角色轉向與踏步的瞬間。也要從出生列向後點擊並檢查兩側視角。爐房的浮雕牆、左右牆面和門洞共用終點的世界座標與透視比例。惡魔、天使與騎士直接刻在磚面，衣褶沿不規則磚縫淡入底材，上方石翼環抱日蝕。從入口檢查日蝕的完整輪廓，再於長旗展開時確認三張臉仍可辨認。兩側砌石保留清楚的輪廓，淡黑陰影只向牆外延伸，與靜態雕刻一併快取，升溫時只疊加日蝕刻痕的反光。兩支暗鐵旗桿各沿一側牆面最上方的水平飾線橫跨整幅，旗布置中。前進、後退及貼牆橫移時，比對旗桿兩端與石縫是否仍對齊。走道與側牆負責遮擋，畫面底緣應始終看得到地面。

### 幽靈與守衛配音

三隻幽靈使用三種自然的美式英文男聲，近距離輕聲招呼玩家。紅、藍、金依序說 “Follow me.”、“This way.” 和 “Come with me.”。混音以清楚的原聲為主，只保留一層極淡的短反射。現版每 2.2 秒換下一隻開口。守衛攔路的音量和語氣更堅定，台詞顯示在說話的騎士頭頂。配音預先輸出為 MP3，遊戲直接播放，字幕與發話者共用同一組狀態。

用全新的瀏覽器分頁進入試煉，點卷軸並按 Begin，等三隻幽靈各說完一次。確認第一個字和尾音清楚、台詞沒有重疊，選好嚮導後招呼聲會停止。

### 重用惡魔音色

以清楚的單人聲乾音為輸入。`tools/alien-voice.ffgraph` 會保留主聲咬字，疊上更高的顫音、略帶失諧的低聲與短促的左右回音。每個惡魔可錄製自己的台詞，用同一份濾鏡預先輸出遊戲音檔。使用支援從檔案讀取選項的 FFmpeg，可在 `castle-below` 目錄執行以下指令。

```sh
ffmpeg -i line.wav -/filter_complex tools/alien-voice.ffgraph -map '[out]' -c:a libmp3lame -b:a 160k demon-line.mp3
```

### 在素材上標定的資料

每張圖的標註用**原始圖的像素座標**。地板與牆使用同一份標註，換圖或重新縮放時要重驗。

| 資料 | 怎麼標 | 用途 |
|---|---|---|
| `art.asset` | 原始場景圖的載入鍵 | 由 `assetFiles` 對應實際 WebP 檔名 |
| `art.outline` | 前三點依序標左側牆頂、後方交角、右側牆頂 | 尋找可用的屋脊和石材輪廓 |
| `art.floorCorners` | 從後方交角開始，依右、前、左標四個地板角，落在石板上平面 | 把大小與坡度不規則的生成素材對準房間格線 |
| `opening`、`otherOpening` | 在左、右照片牆上描出門洞內緣的 SVG 路徑 | 換成透明孔洞，同一路徑供點門命中判定 |
| `link.jambs`、`link.sill` | 門柱兩側的來源 x，加上對應的門檻 y | 把視覺門寬、地板接點及通行範圍同步到世界座標 |
| `art.windows` | 每面玻璃的光暈中心 | 隨牆面配準一起投影，中央雕像位置跳過 |
| `art.stairCorners`、`art.stairJambs` | 地板樓梯井四角、牆上樓梯口兩側 | 計算樓梯井排除範圍、走到樓梯前的位置 |
| `art.statue.footprint`、`art.statue.outline` | 底座接地四角與可見外輪廓分開描 | 底座碰撞、石雕獨立深度合成 |
| `art.mirror` | 全房間照片左右鏡射時設為 `true` | 同步交換對應牆軸與地板角，門柱標註保持原圖座標 |

### 對齊方法

- **地板從世界矩形投影。** `rawIso` 用 `screenX = (x − y) × 44`、`screenY = (x + y) × 22 − z`。x、y 是格，z 是畫面高度單位，地面是 `z = 0`。地板碰撞、牆高和門平面都從這組座標取得。
- **修正素材透視。** 地下檔案室原圖就是例子。它的近側與遠側斜率不同，房間尺寸由世界矩形定義。用 `floorMesh` 以左右後牆的牆腳剖線插值成連續小網格，再用 `surfaceTriangles` 把每塊地板投到同一個矩形。門柱所在的點加入網格分區，讓門檻和地板共用邊。用 `pointOnSurface` 在兩套座標間往返，雕像和樓梯的落點跟著圖移動。
- **每面牆單獨配準。** `roomGeometry` 用同一條世界牆腳和同層共用牆高展開牆面。試玩版一樓是 462、地下室是 318 畫面高度單位。前景外牆也用 `wallHeight`。外牆材質依樓層選擇，沿實際邊界裁切到需要的長度。
- **剔除原圖背景。** `photoRoofline` 以牆頂標註為初值，在原圖邊線附近辨識連續的石材像素，再往內採樣少量像素。用快取重用輪廓。各三角形剪裁邊留約 1 像素重疊，最外側仍受地板或牆面輪廓裁切，可避免拼圖和反鋸齒時露出細黑線。
- **每道共用牆有一份實際牆面。** `exteriorEdges` 將已有相鄰房間接合的區段從外牆扣除，兩室間使用 `link.after` 對應的後牆圖層。在接黑區的剩餘區段建立外牆、壓頂和薄基座，房間之外保留深色空間。
- **門的畫面、點擊和碰撞共用定位。** 用 `destination-out` 挖去門洞內側，保留真石門檻和門柱。門洞裡渲染相鄰房間的實際景色。點擊時從畫面反投影到牆圖做 `Path2D` 命中，通行時使用重新計算的兩門柱之間區段。
- **只在半透明處融合地板。** `buildFloorJoint` 在共用邊兩側約 1.25 格建立融合帶，各自往內約 1.85 格取樣乾淨的石磚，用沿邊與跨邊的漸層混合，最後把兩半裁回各自房間。融合層放在地板上、牆及道具下，透明度隨共用牆淡出從 0 變 1。牆不透明時，用原本的柱腳、接地陰影和濕石反光。門檻石材由牆圖保留。

正式版可以在素材處理階段產出牆圖層、地板和遮罩，再由引擎快取。保留同一份原圖定位資料與世界座標轉換，就能更換畫面實作並重複驗收。

## 3. 相機、角色深度與牆面透視

1. 用角色的世界腳點和高度算相機位移。`updateCamera` 對準角色腳點上方約角色畫面高度 48% 的位置，因此 Coji 的身體留在視窗中央，地板、牆、門、道具與怪物一起移動。點擊平地時先減去相機位移，再做 `rawToWorld`。
2. 依角色所在的房間選牆。世界 `x = right` 與 `y = bottom` 對應鏡頭前方兩側，整面牆平滑淡到 **42% 不透明度**。位於左、上邊界的後方兩面保持完整。共用拱門從一側走到另一側時，前後牆狀態依房間重新判定。
3. 某面相鄰外牆即使在另一個房間，投影仍可能蓋在目前房間上。用 `exteriorWallOccludesRoom` 檢查牆面投到地板的區域是否與目前房間相交。高度 z 的牆面點在地面的投影會讓 x、y 同時減少 `z / 44`。有交集的其他房間側外牆淡出，避免它在剛穿門時恢復成一整片擋住門框。保留不遮住目前房間的外牆。
4. 按 `floor.rooms` 的遠近順序逐室繪製。角色、怪物、光球與粒子依世界腳點歸入房間。遠側房間畫完後才畫近側房間的共用牆，牆圖的透明門洞會露出後方的人物。
5. 每間房先畫地板、接縫和後牆，再按腳點深度交錯繪製燈柱、雕像、角色與道具，最後畫前方外牆。小怪的名字與血條跟著本體一起畫，門柱也能遮住血條。
6. `updateWallOpacity` 依 Coji 所在房間決定哪些牆淡出，使用 `1 − exp(−16 × dt)` 平滑過渡。同一牆面的數段共用一個 `face` 和透明度。

參考 `buildWorld`、`isRoomForegroundWall`、`updateWallOpacity`、`render`。

## 4. 移動、穿門、上下樓

- **點擊優先序**是樓梯、寶箱或掉落物、同層拱門、Coji 防禦、存活怪物、地板。`onPointerDown` 用 Canvas 的 CSS 相對座標命中，互動按鈕則呼叫相同的排程函式。蓄力中、樓梯轉場中或高遮黑階段暫停新指令。
- **尋路**用八鄰接 A*，直走代價 1、斜走 √2、八向距離估計。地板範圍與阻擋格從房間規格建立，樓梯井和雕像底座用多邊形檢查，寶箱佔所在格。斜走須讓兩個相鄰直走格也能通行。點在不可當作落腳點但仍在地板範圍內時，尋找最近的可走格。
- **同層門**把角色引到門對面約 1.5 格處。門的位置來自配準後的門檻，跨牆格要正向穿過門，腳點與每側門柱保留 0.32 格。角色走過界線時更新 `room` 與房名，保持相機和腳點連續。同層的怪物、寶箱和已拾取物品沿用原狀態。
- **移動速度**為 Coji 每秒 3.4 格。每個更新最多前進 `speed × dt`，抵達下一點後取下一個路徑節點。常規格點用格心。門前改點方向時，離開目前格以前用格心重新對準跨牆步驟。
- **樓梯**先用尋路走到 `approach`，抵達後執行 `passage`。下樓 1.52 秒、上樓 1.35 秒，平面過程用 `progress^2.15`。前段逐步轉黑，到進度約 42% 時已全黑。下降高度依腳點進入井口的距離計算，上樓的高度變化在全黑後開始。轉場結束才換樓層和到達點，之後淡入，避免腳與樓梯圖片錯位。
- **入口和復位**使用走得到、離碰撞體有空隙的出生點。首次進入和「重置」都從地下試煉長廊的岩漿門前開始。樓梯轉場會清空當前移動、投射物、粒子和排程，保留已拾取物品。「重置」才清空寶箱與拾取紀錄。

參考 `roomAt`、`isWalkable`、`canCrossWall`、`findPath`、`moveAlongPath`、`queueLinkedRoom`、`startPassage`、`updatePassage`。

## 5. Coji 美術、動畫與魔法

### 精靈表和貼地

- Coji 的帽子、眼鏡、制服、身形及抱著的 Bebear 維持同樣設計。Bebear 是白色圓頭、藍耳朵、棕色鼻子，連著條紋安撫巾。製作待機、走路、施法、防禦時沿用這套外形、比例和配色，讓動作銜接時像同一個角色。
- 一張標準 Coji 精靈表是 **4 欄 × 2 列**，由左至右、由上至下的索引 `0–7` 對應下、左下、左、左上、上、右上、右、右下。運行時索引 1、2、3 分別鏡射 7、6、5。獨立的右上施法圖為 1×1，覆蓋施法索引 5，左上從這張圖鏡射。
- `coji-walk-a.webp` 到 `coji-walk-h.webp` 是依時間排列的八個關鍵幀，每幀都有方向格。現有 G 表的右上格使用修正映射。配準和插幀已預先烘焙到 `coji-walk-cycle.webp`，五欄依序是方向 0、4、5、6、7，每列代表一個相位。
- 播放時一個腳步 **8 幀**，左右腳完整一輪 **16 幀**，約 0.63 秒。相位每秒加 10，選幀間隔 `2π / 16`。腳步塵粒子在相位跨過 `π` 時發出。選幀在 `currentCojiFrames`。
- 每格預留足夠的透明範圍容納帽尖、手和腿，並將頭、身體與著地腳對齊。腳底與身體輪廓已記錄在 `scenes/sprite-frames.js`。繪製時從圖集取出該格，以腳底為錨點。試玩版 Coji 畫面高度為視窗高的 20.25%，限制在 109–143 px。校稿時逐格看完整一輪，也要連續看動作與落腳。腿被裁、身體抖動或腳滑先從單格比例和錨點查起。
- 顯示優先序為施法、舉盾、走路、待機。走路用精靈表本身的身體運動。待機加輕微呼吸和擺動，施法加短暫前傾。每個動作都沿用同一腳點與深度。

### 施法與光暈

- 點存活敵人時，世界距離 9 格內才能施法。超距只轉向並提示。施法開始取消移動，動作長 0.78 秒，約在進度 43% 釋放，下一發間隔約 0.94 秒。施法期間會追蹤目標朝向。
- 從世界方向投影到畫面再分八向。接近水平的視覺姿勢使用同側前方斜向手勢。往上達到約 **8°** 即能選擇後方斜向施法。由這張實際顯示的圖定義蓄力光與發射點。普通光球起始高度是 82，斜上依專用圖高度、腳底偏移和投影前移量定位，避免亮點和手勢分離。
- 光球沿目標方向追蹤，速度 9.5 格／秒、壽命 1.5 秒，帶短尾跡和輕微高度浮動，抵達目標時判定命中。`clearShot` 在施法和光球移動時檢查射線與門柱的交點；光球能穿過拱門，碰到實牆會消散。
- 移動和待機共用小光暈，尺度基準為 .76。移動時只做連續亮暗脈動，目標強度約 .08–1。待機慢慢回到固定強度。蓄力和防禦擴大光暈，發射後平滑收回。光暈使用持續的狀態值，以 `1 − exp(−6 × dt)` 追隨目標，走停切換不會把光暈清掉再重生。
- 按住 Coji 時捕捉該次 Pointer，停下並進入防禦。抬手、取消，或滑鼠離開時解除。受到攻擊而正在防禦只出現防禦特效與提示，HP 維持。

參考 `rebuildSpriteCaches`、`cojiFrameForFacing`、`facingForVector`、`orbLaunchPoint`、`updateCast`、`updateCojiAura`、`endGuard`。

## 7. 照明、畫面與觸控

### 照明與材質

- **室內燈柱**用透明底圖，底座對準世界地板上的腳點。後牆沿房間寬度四等分，放在每段中點，距牆約 1.9 格。留出門洞兩側空間，跳過雕像底座，入口兩側可各設一支。保持原素材比例，基準高度 112 px。底座無獨立投影，暖色光跟著燈柱在同一場景分層裡渲染，讓前方牆可遮住燈光及燈身。地面反光短且淡。
- **窗光**每面玻璃各有一個定位點，跟牆的配準一起變換。使用冷色的 `screen` 光暈與較扁的地面反光，乘上牆當下的不透明度。玻璃大廳六個定位點使用較慢較廣的循環，每一面有相位差。原圖亮度保留，由動態光暈增加明暗變化。
- **玻璃大廳調校**以 `pulse = (1 + sin(t × .94 + index × 1.92)) / 2` 控制，光暈 alpha 為 `.035 + .965 × pulse^1.5`，兩方向半徑由 `72 × 115` 逐步拉到 `162 × 247`，反光用光暈 alpha 的 .61 倍。遺忘大廳用頻率 1.65、alpha 約 .08–.90、反光倍率 .42。這些值以圖上有窗的區段使用。
- **氣氛**以淡霧、暗角與少量粒子統一各房間的色調和深度。用「畫面效果」開關觀察對比，人物、門洞及可拾取物品必須可辨。Coji、怪物和光球的效果附著於各自的位置及狀態。

### 介面和執行迴圈

- 從 Games Made by Kid 主選單啟動 Castle Below，遊戲在整個可用視窗渲染，返回入口設在 HUD。「設定」收納畫面效果、格線與重置。Canvas 的高度隨 `visualViewport` 更新，HUD 和門口按鈕依裝置安全區避讓。支援的瀏覽器可用「全螢幕」切換原生顯示，主畫面網頁 App 透過主選單的 manifest 保持在同一個遊戲網站內。
- HUD 顯示 Coji 的心、敵人血條、房名、房間提示與拾取計數。點地時用短暫的地面標記指示目的地。敵人血條與短訊息錨在對應物件的畫面位置。
- 門、樓梯、寶箱和掉落物也有 DOM 按鈕。依世界錨點定位，限制在視窗內，並在靠近其他按鈕時垂直錯開。只有目前房間的相關按鈕可見。直接點畫面和點按鈕走相同的互動流程。用 Pointer Events 共用滑鼠和觸控。
- `requestAnimationFrame` 每次更新先推進時間、路徑及玩家狀態，再處理敵人、飛行物、粒子、光暈和相機。每次模擬更新的 `dt` 上限為 .04 秒。正向試煉可將較長的影格間隔拆成多次更新後再繪製。Canvas 瀏覽器裝置像素比上限 1.5，世界投影與點擊用 CSS 像素計算。以離屏 Canvas 快取房間分層、精靈格和光暈。畫面尺寸變動時重建必要的精靈快取與相機位置。
- 上一層場景與下一層場景各用獨立的房間資料。試玩版在進入樓層或必要素材載入時建立圖層，必要素材載入失敗時顯示「重試」，成功後才切入場景。正式版可預先產出房間圖層及導覽資料，以相同的座標模型和畫面驗收標準控制載入成本。

## 9. 正式版驗收順序

先在同一場景逐項比對試玩版，再換圖與增加房間。畫面規格之外，也要看操作後的結果，例如真的走過門、真的到箱前才開箱。

### 2.5D 效能驗收

每次修改場景、材質或特效，都要用相同路線比較修改前後的幀時間。以目標裝置的 60 Hz 模式為基準，每幀的更新、繪製與合成共用約 16.7 ms。走動或轉場特效持續掉幀、反覆出現超過 33 ms 的畫面間隔，或點地後有明顯遲滯，都要修正並重測才能通過。

1. 記錄裝置、瀏覽器、視窗大小、實際 Canvas 像素比與特效設定。在桌面及目標手機實機各測一次，首次進房另記載入時間及第一次操作的停頓。
2. 開啟瀏覽器效能錄製，從地下室進入岩漿長廊，讀卷軸、沿側牆走動，經過預警、噴發及冷卻，再走到終點開門。各階段分開看平均 FPS、幀間隔第 95 百分位及超過 33 ms 的幀數，同時檢查主執行緒、點陣繪製與合成耗時。
3. 幽靈房開啟火柱與三色光暈，沿兩側移動，再跟隨幽靈穿過鐵柵。分別記錄第一次進入守衛房、雕像房及再次進入時的載入停頓。
4. 發現退步時，固定格子配置、鏡頭路線、視窗與熱度，每次只停用一層，例如煙霧、終點牆或地板，再錄一次。修正後以完整特效重跑，從入口與終點兩側確認煙霧、牆面、旗幟的遮擋仍然正確。
